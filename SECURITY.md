# Security Policy

## Supported versions

DomLingo is in pre-release development. Security fixes are applied to the latest development
version until the first stable release defines a longer support window.

## Reporting a vulnerability

Do not open a public Issue containing:

- API keys or authentication headers;
- private webpage content;
- browser profiles, cookies, or session data;
- an exploit for an unpatched vulnerability.

After the public GitHub repository is created, use GitHub Security Advisories to report
vulnerabilities privately. Until then, report the issue to the project maintainer through a private
channel and include only the minimum data needed to reproduce it.

Reports should include the affected version, impact, reproduction steps, and a safe proof of
concept. Never use third-party private data when demonstrating a vulnerability.
